# 문제

**쌀먹 0.1은 메뉴 막대 표시 결함을 별도 AppKit 도우미 구조로 교체하는 중이다.** 로컬 통합 배포 앱에서는 실제 픽셀·클릭·우클릭·도우미 자동 복구 검증을 통과했다. GitHub 새 환경의 전체 빌드와 최종 설치본 재검증이 끝나기 전까지 완료 상태로 되돌리지 않는다. Apple 공증과 실제 초기화권 사용 시험도 아직 실행하지 않았다.

# 해결

- 설치본: `/Applications/쌀먹.app`
- 로컬 저장소: `/Users/godju/Downloads/AI App/ssalmeok`
- 가장 적게 남은 서비스를 메뉴 막대 항목 하나로 표시하고 공식 로고 옆에 남은 사용량을 붙인다.
- 항목을 우클릭하면 Codex·Claude 한도·초기화까지·토큰·원화 환산을 창 없이 함께 확인한다.
- 접이식 30일 기록에서 Codex 작업별, Codex·Claude 모델별 토큰과 원화 환산을 확인한다.
- 창에서는 서비스별 한도 창, 남은 비율, 초기화 카운트다운, 최근·30일 토큰과 비용 추정치를 보여준다.
- 자동 갱신을 실계정으로 연속 2회 확인했다. 이 과정은 AI에게 질문하지 않으므로 토큰을 쓰지 않는다.
- Codex와 Claude 모두 한도 창 3개와 토큰 집계를 정상 수신했다. Codex 초기화권 1장도 조회됐다.
- 초기화는 버튼 → 별도 경고창 → 확인 체크 순으로 잠겼고, 체크 전 최종 버튼이 비활성인 것을 확인했다. 실제 초기화권은 사용하지 않았다.
- 초기화 요청은 OpenAI 공식 방식으로 보유량 재확인 → 중복 방지값 저장 → 1장 사용 → 사용량 재조회 순서로 구현했다.
- 계정 이메일·인증 정보·초기화권 식별자는 화면과 캐시에 남지 않는 것을 확인했다.
- 로그인 시 `/Applications/쌀먹.app`이 창 없이 시작하도록 등록됐다.
- Dock에는 나타나지 않고 메뉴 막대 항목 하나만 유지된다. 본창은 필요할 때 생성되고 닫으면 화면 렌더링이 해제되지만 메뉴 막대 프로세스는 계속 살아 있다.
- 현재는 본창을 닫아도 Tauri 수집기와 작은 AppKit 도우미가 함께 유지된다.
- 한도 조회는 1분, 무거운 토큰·비용 기록은 10분 간격으로 나눴다. `지금 갱신`은 둘 다 즉시 실행한다.
- 대기 메모리는 약 145MB에서 약 66~67MB로 줄었고, 설치 용량은 46MB에서 28MB로 줄었다.
- 새 분리형 통합 앱의 로컬 실측은 Tauri 23,760KB + AppKit 도우미 24,352KB, 합계 48,112KB였다.
- 화면 검사 4개, 앱 본체 검사 7개, 엄격 경고 검사, 배포 빌드, 앱 전체 임시 서명이 모두 통과했다.
- 설치본과 최종 빌드의 주 실행 파일·보조 프로그램 해시가 각각 일치한다.
- 공개 저장소: `https://github.com/ljhljh0703-cmd/ssalmeok`
- GitHub 새 macOS ARM 환경에서 전체 검사·앱 패키징·압축 결과물 업로드가 통과했다.

토큰 비용은 실제 청구액이 아니라 API 정가로 환산한 추정치이며 화면에도 그렇게 표시했다. 자세한 사용법은 `README.md`, 실제 검사와 미실행 범위는 `docs/VERIFICATION.md`에 있다.

# 다음

지금 열린 쌀먹을 잠깐 사용해 보고 아래 세 가지만 확인한다.

1. 메뉴 막대 로고 크기와 남은 비율 사이 간격이 적당한지
2. 가장 부족한 한도를 대표값으로 쓰는 방식이 직관적인지
3. 창에서 정보가 너무 많거나 부족한지

공개 GitHub 저장소의 `main` 브랜치에 소스가 올라갔다. 빌드 캐시·다운로드된 보조 프로그램·인증정보는 원격 파일 목록에서 제외된 것을 확인했다. GitHub Release와 불특정 사용자용 공증 배포는 아직 하지 않았다.

GitHub 원격 재빌드 성공을 확인한 뒤 사용자 승인으로 개발용 Rust 빌드 캐시를 정리했다. 이번 교체 확인은 저장소 캐시를 다시 만들지 않고 별도 임시 빌드 공간에서 진행하며, 최종 확인 뒤 그 공간도 정리한다.

## 메뉴 막대 표시 문제 정정

기존 기록의 “메뉴 막대 항목 확인”은 접근성 객체 존재와 일부 화면 관측을 섞어 쓴 표현이었다. 백그라운드 최적화 이후 실제 픽셀을 매 릴리스 관문으로 남기지 않아, 항목이 화면 밖에 있어도 통과로 오판했다. 현재는 Tauri 본체와 별도 AppKit 도우미를 분리했고, 좌표와 실제 잘라낸 화면을 함께 확인해야만 통과하도록 검사기를 추가했다. 상세 원인·배제 과정·재발 방지 기준은 `docs/INCIDENT-2026-09-MENUBAR-VISIBILITY.md`에 기록했다.
