# 메뉴 막대가 존재하지만 보이지 않았던 문제

## 문제 정의

쌀먹 프로세스와 메뉴 막대 접근성 항목은 존재하고 클릭 메뉴도 생성됐지만, 사용자가 보는 화면에는 아이콘이 없었다. 문제의 핵심은 “트레이 객체 생성 실패”가 아니라 “생성된 항목이 화면 밖 좌표에 배치되는 현상”이었다.

## 현행 완료 기준과 변경 경계

사용자 최종 기준(2026-09-13): **Codex 주간 잔여율과 Claude 5시간 잔여율을 각 로고 옆에 동시에 표시한다.** 클로드의 24시간 일일 한도는 현재 계정 데이터에 없으므로, 사용자가 5시간 기준을 선택했다. 가장 부족한 서비스 하나를 고르는 이전 결정은 대체됐다.

- 통과 증거: 최종 설치본 해시와 실제 픽셀을 함께 기록한 최초 실행 + 재실행 2회, 총 3회. 상세 영수증은 아래 최종 검증 절과 VERIFICATION.md 참조.
- 원인 상태: 화면 밖 배치 현상과 프로세스 분리 시 관측 차이는 기록됐지만, 최초 성공에서 실패로 바뀐 정확한 내부 원인은 **unknown**이다.
- 추가 시험 경계: 장시간·절전 복귀·다중 모니터는 **not run**. 이전 판본의 클릭 시험을 최종 판본의 증거로 승계하지 않는다.
- 이번 사용자 범위 밖의 클릭·메모리·원격 빌드 검사는 별도 항목이다. 이미 통과한 표시 복구를 이유 없이 미완료로 되돌리거나 범위를 늘리지 않는다.

### 재발 시 최소 대응 순서

1. 먼저 이 repo와 설치본을 변경하는 작업이 하나인지 확인한다. 정상 기준은 아래 보존본이다. 실행 파일이 달라졌는지 먼저 확인한다. 실패 앱을 덮어쓰기 전에 해시·실행 조건·화면 증거를 남긴다.
2. 검사 도구 오류, 데이터 오류, 실제 배치/픽셀 오류를 구분한다. 조회 오류나 빈 캡처만으로 앱 코드를 수정하지 않는다.
3. 표시 회귀라면 정상본과 실패본을 같은 조건에서 비교한다. 조건 하나만 바꾸고 예상되는 두 결과와 다음 행동을 적는다.
4. 같은 가설에서 새로운 구분 정보가 나오지 않으면 더 수정하지 않는다. 화면 공간·운영체제·도구 권한처럼 사용자 선택이 필요한 제약은 그 증거와 최소 선택지만 보고한다.
5. 복구가 검증되면 멈춘다. 원인 미확인은 별도로 남기며 새 프레임워크·의존성·감시 시스템으로 범위를 확대하지 않는다.

## 자동으로 막는 재발과 한계

- 구조 검사: 기존 Tauri tray 및 같은 프로세스의 실패한 구현 재연결 차단. 이는 현재 검증된 구현을 보호하는 프로젝트 검사이며 해당 기술을 영구 금지한다는 뜻은 아니다.
- Rust 검사: Codex 기본 주간과 Claude 기본 5시간을 선택하며, 더 적게 남은 scoped/주간 값으로 바꾸지 않는다. 요청한 기본 한도가 빠지면 대시로 처리한다.
- 화면 검사: 두 항목이 화면 상단에 함께 있어야 하며, 실제 로고+비율 확인 전에는 pixel_gate=pending이다. 실패 좌표와 조회 오류를 파일로 남긴다.
- `pnpm test:menubar-verifier` → `pnpm verify` 첫 단계: **4개 실패 경로 검사**. 조회 오류, 항목 하나 누락, 화면 밖 항목, 픽셀 미검토에서 거짓 통과가 나지 않는지 확인한다. 모든 OS 명령은 테스트 대역이며 실제 UI/화면 검증으로 계산하지 않는다.
- 자동 검사는 시각 판정을 대신하지 않는다. 새 설치본에 현재 영수증을 재사용하거나, 장시간 안정성을 보장한다고 쓰지 않는다.

## 왜 처음에는 됐나

최초 실행 때 실제로 보였다는 사용자 관측은 유효하다. 그러나 당시에는 다음 실행까지 포함한 반복 화면 증거를 남기지 않았다. 나중에 같은 초기 실행 파일을 다시 돌렸을 때도 보이지 않았으므로, 최초 성공 당시의 실행 조건과 이후 재시험 조건이 같았는지 추가 대조가 필요하다. 최초 성공이 일시적이었다고 확정할 근거는 부족하다. 정확히 어떤 macOS 상태 변화가 최초 성공을 만들었는지는 확인 불가다.

- 최소 지원 버전 14 설정이 문제다.
- `autosaveName` 위치 복원이 문제다.

각 항목을 바꾼 시험이 있었지만, 서로 다른 프로세스/실행 조건의 결과로 모든 상호작용을 배제할 수는 없다. 최초 기술 원인은 미확인으로 유지한다.

## 해결

- Tauri 본체는 본창, 데이터 수집, 자동 시작, 알림만 담당한다.
- 약 100KB인 별도 Swift 도우미가 AppKit의 `NSStatusBar`와 `NSStatusItem`을 소유한다.
- Tauri가 JSON 한 줄로 표시 상태를 보내고, 도우미는 `toggle`, `open`, `refresh`, `quit` 동작만 돌려보낸다.
- 부모의 입력 파이프가 닫히면 도우미도 종료되고, 도우미만 비정상 종료되면 Tauri가 2초 뒤 다시 시작한다.
- 현재는 Codex 주간과 Claude 5시간을 두 로고 옆에 각각 표시한다. 한 항목으로 줄였던 중간 구현은 대체됐다.
- 왼쪽 클릭은 본창 열기·닫기, 오른쪽 클릭은 두 서비스의 전체 상세 메뉴를 담당한다.
- Tauri `tray-icon`, 같은 Tauri 프로세스 안의 AppKit 직접 생성, 로컬 우회 패치는 모두 제거했다.

## 재발 방지

### 자동 구조 관문

`pnpm verify`가 `scripts/check-native-tray-boundary.sh`를 먼저 실행한다. 다음 중 하나라도 생기면 CI가 실패한다.

- Tauri의 `tray-icon` 기능 재활성화
- `TrayIconBuilder`, `tauri::tray`, `with_inner_tray_icon` 재도입
- 로컬 `tray-icon` 우회 패치 재연결
- Tauri 프로세스 안의 AppKit 상태 항목 재도입
- Swift 도우미, 부모 연결 코드, 앱 묶음 설정 중 하나라도 누락

### 실제 화면 관문

설치 또는 메뉴 막대 생명주기 변경 뒤 `pnpm verify:menubar`를 실행한다.

- 다른 쌀먹 본체나 메뉴 막대 도우미가 있으면 즉시 실패한다.
- 지정한 앱을 `--hidden`으로 직접 시작한다.
- 별도 AppKit 도우미가 하나이고 상태 항목은 정확히 두 개인지 확인한다.
- 시작 직후의 임시 프레임을 통과로 오인하지 않도록, 같은 화면 안 좌표가 두 번 연속 관측되는지 확인한다.
- 상태 항목 부분만 PNG로 저장해 개인정보 노출 범위를 줄인다.
- 사람이 PNG에서 로고와 남은 숫자를 모두 확인해야 최종 성공 영수증을 쓴다.
- 영수증과 PNG는 공개 저장소에 올라가지 않는 `.runtime-evidence/`에 보존한다.
